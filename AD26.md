# Altium 26 compatibility

The upstream v1.0.1 release targets .NET Framework 4.8 and DevExpress 22.1. Current upstream source targets .NET 6 but retains the old assembly references. Altium 26.10.1 supplies .NET 8.0.15 and DevExpress 25.2, so the released plugin is not compatible as shipped. This fork builds against the SDK and UI assemblies from the installed AD26 directory.

## Changes

- Retargeted the plugin and standalone viewer to .NET 8, x64 and the installed AD26 SDK. Updated the standalone viewer's HelixToolkit dependency and SDK lookup. Its downloads now run asynchronously with cancellation and error handling.
- Corrected circle field parsing, top/bottom pin centering and the signed height offset for 3D models. Temporary STEP files are cleaned up after failures.
- Reused HTTP connections, enabled Brotli decompression, corrected thumbnail URLs and description parsing, and propagated download failures and cancellation.
- Prevented overlapping searches and callbacks after closing the dialog. Symbol-only imports no longer require a footprint or active schematic.
- Balanced PCB and schematic edit transactions, switched back to the schematic library before creating symbols, and restored the original document after failures.
- Fixed deployment argument forwarding, locale-dependent registry dates and missing release helpers. Deployment now removes stale dependencies, rejects ambiguous installations and backs up the previous files.

## Verification

Tested on the installed **Altium Designer 26.10.1**, running under Wine-staging 11.16 on Apple Silicon:

- Plugin and standalone builds: zero warnings or errors.
- 20 regression checks passed under Altium's bundled .NET 8 runtime, covering parsing, pin layout, model height, temporary files, HTTP errors, cancellation, URL handling and actual Brotli responses.
- Five Python deployment tests passed, including rollback after a simulated registry write failure.
- PowerShell deployment tests passed for install/update, version updates, French locale dates, preserving other extensions and rejecting malformed registry XML.
- Native Altium smoke test: extension menu and dialog loaded; live `C2040` search and RP2040 previews worked; imported and saved the symbol, footprint and embedded STEP model into separate scratch libraries. Schematic placement was disabled for this test.

The smoke-test libraries are in `~/AltiumWine/examples/EasyEDA-Test/libraries`. Altium was launched with `EASYEDA_LIBRARY_DIR` pointing there; ordinary launches use `Documents/AltiumEE` unless that variable is set.

The optional standalone viewer compiles, but its window rendered transparently in the Wine smoke test. A software-rendering workaround did not resolve this and was not retained. The extension's dialog and imports worked inside Altium.

Complex or multipart symbols and precise 3D X/Y placement still need broader testing. Placement into an active schematic was not exercised in the smoke test.

## Run the checks

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
pwsh -NoProfile -File tests/Test-Deployment.ps1
```

Publish the Windows regression runner with the installed SDK path:

```sh
dotnet publish tests/RegressionTests.csproj -c Release --self-contained false \
  -p:AltiumInstallDir='/path/to/Altium/AD26'
```

Run `RegressionTests.exe 'C:\Program Files\Altium\AD26'` on Windows. Under Wine, point `DOTNET_ROOT` and `DOTNET_ROOT_X64` to `C:\Program Files\Altium\AD26\System\DotNet\Runtime` and use the existing `altium-wine.sh wine` launcher.

For a macOS deployment preview, run `python3 tools/deploy-wine.py --dry-run`. Its printed backup folder contains the previous registry and extension directory for restoration while Altium is closed.
